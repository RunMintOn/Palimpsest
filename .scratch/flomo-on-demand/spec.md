# Flomo 按需调用 Palimpsest 检索：第一版

Status: resolved

## Problem Statement

用户希望在 Flomo 浏览一张卡片时，主动查找当前空间内的相关旧记录，并直接查看命中原文、打开来源。无需为此打开 Markdown 编辑器，也不希望 Flomo 复制索引、配置第二套模型或理解内部片段结构。

原接入草案同时考虑了自动索引维护、可见使用方登记、状态订阅与重连。本次仅实现“点击一次，查询已有索引一次”，用较低成本先提供可用功能。用户已接受：只使用 Flomo 时，Palimpsest 索引不保证自动更新；需要时打开 Palimpsest 让原流程处理更新。

## Solution

Flomo 卡片提供“找相关”操作。点击后读取该文件的当前 Markdown 正文，去掉 frontmatter，以当前空间全部有效记录为候选，调用 Palimpsest 的版本化文本查询入口。返回每文件一个代表片段，在 Flomo 展示并支持打开文件。

第一版没有外部自动更新、状态订阅或持久连接。查询使用已有的已提交索引；查询失败与成功零结果有不同表现。用户可以手动重试或重新查询。

```mermaid
flowchart LR
    F[Flomo 点击找相关] --> Q[正文快照、候选路径、来源路径]
    Q --> P[Palimpsest v1 文本查询]
    P --> I[已有已提交索引]
    I --> R[每文件最佳片段]
    R --> U[Flomo 结果与打开来源]
```

## User Stories

1. 作为 Flomo 用户，我希望点击一张卡片的“找相关”，以便围绕该记录回看旧笔记。
2. 作为用户，我希望无需打开该卡片的编辑器，以便保持浏览流程。
3. 作为用户，我希望搜索覆盖当前空间全部有效记录，以便未翻页的笔记也能被找到。
4. 作为用户，我希望当前卡片不出现在结果中，以便结果提供其他内容。
5. 作为用户，我希望同一文件只占一个结果名额，以便看到不同记录。
6. 作为用户，我希望看到真实命中原文，以便理解关联依据。
7. 作为用户，我希望可以打开来源，以便继续阅读；位置过期时仍能打开文件。
8. 作为用户，我希望新卡片尚未索引也能作为查询输入，以便查询不依赖来源记录先入库。
9. 作为用户，我希望没有相关结果和检索不可用能够区分，以免被错误空结果误导。
10. 作为用户，我希望明确知道使用的是已有索引，以便理解最近修改可能还未被检索。
11. 作为用户，我希望索引尚未建立或不兼容时得到操作提示，以便自行到 Palimpsest 处理。
12. 作为用户，我希望快速切换卡片时只显示最后一次请求结果，以免上下文混乱。
13. 作为用户，我希望 Flomo 查询不覆盖 Palimpsest 侧边栏，以便两者可以同时使用。
14. 作为用户，我希望插件缺失、关闭或版本不支持时仍能记录、编辑和每日回顾。
15. 作为用户，我希望一次查询不会自动建库、应用范围或触发大规模更新确认，以便查询成本和行为可控。
16. 作为维护者，我希望两个插件只依赖一个小型查询约定，以便内部算法与索引结构可以变化。

## Implementation Decisions

### 共同契约与职责

- 本 spec 是第一版共同真相源；原接入草案作为后续能力参考，不要求实现其全部行为。不创建第二份完整协议副本。
- Palimpsest 管理索引、模型、召回和排名。Flomo 管理卡片输入、候选集合、请求序号和结果展示。
- Palimpsest 插件实例提供名为 retrievalApi 的入口，包含字面版本 apiVersion = 1 和异步 query 方法。协议仅使用普通对象、字符串、数字和数组，不暴露类实例、向量、chunk ID 或数据库结构。
- Flomo 每次点击或重试时，通过一个集中封装的插件发现 Adapter 获取当前 palimpsest 实例并检查协议版本。允许对 Obsidian 插件管理器做集中隔离的类型适配，必须实测加载顺序和卸载；不新增总线、HTTP、独立服务或共享运行时包。
- 不保存长期连接，不轮询、不自动重连。对正在执行的请求保留短期实例引用即可；卸载后该实例不能发布成功结果，下一次手动请求重新发现当前实例。

### query 输入

- text：调用时已取得的正文快照。Flomo 使用现有 Obsidian frontmatter 工具去除文首属性，不读取渲染后的 HTML，不把标签从正文删除。正文按文件当前内容读取，而非取可能过期的卡片 DOM。
- sourcePath：同 Vault 相对 Markdown 路径，默认排除它的所有片段；来源不需要已索引。
- candidatePaths：必填的同 Vault 相对文件路径数组。空数组表示没有候选，不解释为全库。规范化并去重，拒绝绝对路径及越出 Vault 的路径；不支持通配符和回调过滤器。
- limit：可选，默认 5，必须是 1–20 的整数，以文件计数。返回数量允许少于 limit。
- text 去除首尾空白后不能为空；第一版不沿用编辑器八字符门槛。最多接受 16,000 个 JavaScript 字符长度单位，超限明确提示缩短查询，不静默截断或自动拆成多次模型调用。此上限是协议工作预算，不承诺适合所有模型上下文；实际模型拒绝仍明确返回错误，不改变现有模型配置。
- 候选与正文在调用时取得快照。Flomo 默认候选为当前空间全部有效记录，遵守自身排除规则及日期有效性；不受已渲染页数、当前标签筛选或每日回顾抽样列表限制。不增加候选范围设置。

### query 输出与错误

- 成功响应具有 ok = true、results 数组、knownPendingUpdates 布尔值。每个结果仅要求 filePath 和 excerpt，excerpt 包含 Markdown 原文 text、从 1 开始且包含端点的 startLine／endLine。
- results 顺序为最终排名；零条结果合法。knownPendingUpdates 表示响应时是否已知存在排队变化、正在进行的索引更新、待对账状态、延期更新或范围 pending 等尚未完成工作；false 不代表绝对最新。
- 预期失败返回 ok = false，携带稳定 code 和可展示 message。code 为 invalid-input、index-needed、index-incompatible、temporarily-unavailable、backend-unavailable 或 query-failed。实例已卸载或索引快照在执行中失效可使用 temporarily-unavailable。
- 插件未安装／未启用、接口缺失或版本不支持由 Flomo Adapter 单独提示，不冒充服务端空结果。意外 Promise rejection 由 Flomo 兜底为查询失败，不能破坏原页面。
- 第一版不返回调试分数、索引版本、覆盖率明细或状态流，不做查询缓存，因此不建立缓存失效协议。

### 检索与索引边界

- 查询不要求 Palimpsest 侧边栏可见，不读取其当前编辑器上下文，不共用其 QueryGate 或结果展示状态。
- 使用现有 HybridRetrieval 与正式快照；关键词派生缓存可从已提交内容按需恢复，这不属于扫描 Vault、生成文档向量或发布正式索引。
- 查询不自动触发对账、增量更新、全量建立、范围应用或确认弹窗。无候选的请求在输入和正式索引可用性判断后直接成功返回空结果，不调用模型。
- 候选文件集合与正式索引实际范围取交集；候选未索引不会自动入库，来源未索引不妨碍查询已有候选。不能先取全库最终几条再过滤。
- 继续使用两路有限候选、RRF 和既有去重；文件级入口每文件最多选一个最高排名片段，以该片段决定文件顺序。无需额外文件评分、实体层、分数累加或 reranker。侧边栏原有每文件设置不因此改变。
- 过滤和去重后候选不足时沿用有界扩展；不保证一定填满 limit，不为稀疏候选放弃范围约束。
- 多个请求可以各自完成；Flomo 切卡不取消或废弃别人的查询，也不能使共享关键词同步仅因自身请求过期而失效。模型调用不要求可中断，第一版不引入通用并发调度器。
- 必须使用一致的已提交快照。更新期间不能安全查询时允许 temporarily-unavailable，不要求无阻塞读取旧代。请求结束前检查实例仍有效及索引快照仍可用，不能拼接两代片段或来源位置。

### Flomo 交互

- 时间流与每日回顾卡片均提供显式“找相关”操作，不把单击正文改成隐式查询，不触发编辑或链接默认动作。
- 每个 Flomo 视图只维护一组当前相关推荐及独立请求序号；不为每张卡片创建常驻查询实例。具体布局沿用现有视图，不扩展为界面重设计。
- 正在查询、成功有结果、成功无结果及错误有明确表现。保留手动重试／重新查询；不自动重试循环。
- 结果区域固定说明“基于 Palimpsest 已有索引，最近修改可能尚未更新”；已知 pending 时加强提示。需要建库、不兼容或需更新时，引导打开 Palimpsest 使用其原有操作，不新增跨插件更新入口。
- 快速请求 A 再请求 B，仅 B 可以更新该视图结果。关闭视图、切换空间、来源删除或相关推荐关闭时使当前展示请求失效。普通页面刷新不无条件重发查询，不复用页面整体刷新 epoch 作为检索会话。
- 展示前根据当前有效记录集合过滤已删除、移出空间或被排除的结果，防止异步期间范围变化；这是结果时效保护，不能代替 Palimpsest 的召回阶段过滤。
- 用返回 Markdown 源文和结果文件上下文渲染摘录，不解释分数。打开来源优先使用返回行号；文件内容变化后允许退回打开文件，已删除时提示，不抛未处理异常。

## Testing Decisions

- Palimpsest 通过版本化 query 公开入口测试完整行为，复用现有检索、快照、native 故障和提交测试 seam；模型使用可检查的替身，不测试内部调用次数或 Obsidian 私有字段布局。
- 必测：无侧边栏文本查询、来源未索引、空候选、不足候选、排除当前文件、候选之外大量高排名片段、同文件多片段、文件级排名、输入边界、未建库、不兼容、后端失败、快照改变、卸载中断与两类调用方隔离。
- Flomo 使用同一 v1 普通对象契约的模拟 Adapter 测试按钮到结果展示、超过一页的候选、回顾与标签不缩小候选、失败提示、A/B 乱序、视图关闭、范围变化、插件缺失及下一次重试重新发现。
- 不因前端测试把接口错误统一转换成空数组。无需模型随机相关性断言或全库效果评测。
- 两边分别执行已有类型检查、测试、构建；最后在明确完整路径的独立测试 Vault 联调，无 Palimpsest 侧边栏、已建立的测试索引、两插件同时查询、后端故障与插件重载均须验证。
- 当前 Flomo 既有 E2E 脚本指定了实际使用 Vault，不能直接运行它们作为本次隔离验收；复用前先改为显式目标校验或新建最小隔离用例。只操作测试 fixture，不安装到正式 Vault。
- 记录实际执行的结果和未验证范围。未运行的检查不得勾选完成；不把历史验收当本轮证据。
