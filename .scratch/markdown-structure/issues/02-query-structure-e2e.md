# 02: 一致的当前段落查询与整体验证

**What to build:** 光标所在段落与索引分块使用一致的 Markdown 结构判断，代码中的井号不会让默认查询错误进入等待，真正标题、frontmatter 和围栏分隔行不触发默认查询；完成独立 Vault 中从旧索引升级到结果来源操作的验收。

**Blocked by:** 01 — 正确索引 Markdown 并安全升级旧索引。

**Status:** resolved

## Context

依据 [Markdown 结构 spec](../spec.md)和 [01](01-index-structure-upgrade.md)。本票依赖 01 提供的结构规则及可安全发布的新版索引，复用同一内部结构识别，不再建立一套查询专用围栏正则。

## Acceptance criteria

- [x] 先通过 paragraphQuerySource／QuerySourceCoordinator 写失败测试：围栏中的井号正文可作为有效段落查询，不能误判为真正标题。
- [x] 同一 fixture 经分块和查询两个公开入口，验证围栏、ATX／Setext、frontmatter 的结构判定一致；不检查内部 helper 调用关系。
- [x] 光标位于真正标题行、Setext 标题两行、frontmatter、开启／关闭围栏和空行时返回空来源，展示原有等待语义，不回退全文。
- [x] 围栏正文以围栏内空行为段落边界；查询范围不跨开关围栏、不吸入相邻普通正文；围栏正文中的标题样式字符不构成段落边界。
- [x] 支持 spec 规定的未闭合围栏、长围栏、伪关闭和 CRLF；默认来源仍要求至少八个非空白字符。
- [x] 普通段落按既有空行与标题边界提取；同段移动光标不重复查询，换段后旧响应不能发布，即使文档 buffer 未改变。
- [x] 显式单次选区、跟随选区、全选及阅读视图选区保持原行为；显式输入不被自动来源的 frontmatter／标题过滤改写。
- [x] 面板隐藏、卸载、编辑器状态变化和索引提交后仍通过原有请求有效性检查，不新增查询调度框架。
- [x] 在独立测试 Vault 验证旧版快照载入、重建提示、预览取消保留数据、确认升级和插件重载；说明旧版 incompatible 状态与旧数据保留的区别。
- [x] 在该 Vault 验证围栏／Setext 样例的默认查询和显式选区，结果来源跳转及引用；确保代码注释未污染后续结果标题上下文。
- [x] 实机验收复用当前 native 安装方式，确认完整测试 Vault 路径，保留可重复步骤或脚本及可检查结果。不能访问真实环境时明确标记未完成，不勾选实机验收项。
- [x] typecheck、全套测试和 build 通过；按测试安装需要准备本机 runtime，不操作正式 Vault。
- [x] 最终说明覆盖 spec 的行为、实际执行的验证、未验证项和剩余限制；移除本次临时诊断，不遗留调试日志或把人工样例当相关性效果评测。

## Implementation constraints

仅调整自动段落来源对结构的理解。查询正文仍是段落，不自动扩大为整段围栏或整篇笔记；八字符门槛、原选区操作和 RRF 均不变。

公开 seam 沿用查询来源与响应判定；插件端只做必要衔接。共享规则来自 01，若发现规则缺陷则在同一实现修正，并重跑受影响的索引回归，不复制规则。

不新增诊断平台、reranker、HNSW、重叠窗口或广泛主类重构。本票不再次提升分块版本，除非实施中发现超出已批准 spec 的分块语义变化；遇到这种情况先报告范围冲突。

## Verification and handoff

最终 E2E fixture 使用独立测试数据，不安装到正式 Vault、不读取或重建正式索引。复用已有实验 Vault 时保留其设置及有效范围，测试 fixture 用 Vault trash 清理。测试结果须区分自动化、真实 native、真实 Obsidian，不沿用历史验收数字冒充本次运行。

持久化取消／失败的详细覆盖沿用 01 与原测试；实机至少重新验证预览取消、成功升级和重载，不宣称所有 durable 故障均已实机覆盖。达到 spec 完成条件后停止，不自动开始下一项架构优化。
