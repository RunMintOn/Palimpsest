# 01: 当前段落查询

**What to build:** 用户在原 Palimpsest 中写作时，停笔后默认查询光标所在段落；换段、继续输入或切换笔记后，较早的请求不能覆盖当前结果。保留显式选区、全选查询全文和跟随选区，不引入新检索后端。

**Blocked by:** None (can start immediately).

**Status:** resolved

## Context

依据 [Lite spec](../spec.md)。这是可独立交付的查询来源变化，暂时沿用当前向量检索。它与 02 没有行为上的阻塞关系，但可能修改同一查询协调入口；并行实施时需隔离工作区、谨慎整合，不能互相覆盖。

## Acceptance criteria

以下勾选记录实现与自动化检查完成；真实 Obsidian 交互的最终验收仍由 04 执行，见验证记录。

- [x] 默认查询按光标所在段落提取，以空行与 Markdown 标题为边界；至少包含 8 个非空白字符。
- [x] 光标位于空行、标题或短段落时不退回全文，界面准确显示等待状态；不要把旧结果标成新查询已完成。
- [x] 光标换到另一段会使旧请求失效并按现有调度触发查询；同段内只移动光标不重复查询相同内容。
- [x] 快速输入、换段、换文件、切换视图和异步编辑器加载后的过期响应控制正确；仅比较全文 buffer 不足以作为段落有效性检查。
- [x] 单次选区、跟随选区、全选后显式查询全文保持可用，跟随模式不会被普通光标事件意外关闭。
- [x] 阅读视图仍支持有效显式选区，不从不可见的旧编辑器光标推断默认段落。
- [x] 侧边栏范围标签、提示与等待状态反映实际来源；来源打开、链接、引用与现有展开操作保持正常。
- [x] 自动查询仍受面板可见性、索引可用性与插件卸载约束。
- [x] 增加针对换段后过期响应和空段不退回全文的行为回归测试，保留其他正确的查询来源、调度与可见性测试。
- [x] typecheck、相关测试和构建通过；记录本票已验证内容及尚待 04 真实 Obsidian 验收的行为。

## Implementation constraints

只做完成上述路径所需的来源与生命周期调整。不加生成式查询改写、邻段自动扩展、用户可配置段落算法或广泛重构。不改索引存储、模型或检索效果定义。

沿用现有公开行为 seam，必要的纯段落提取可独立测试；不要为测试侵入 Obsidian 私有编辑器状态。

## Verification and handoff

未经明确要求不提交、不发布、不操作正式 Vault，保留用户已有修改。
