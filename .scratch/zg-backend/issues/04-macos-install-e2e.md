# 04: 本机独立安装与完整验收

**What to build:** 用户在当前 Mac 的独立 Obsidian 测试 Vault 中安装原 Palimpsest，不依赖开发仓库路径即可完成当前段落混合检索、来源操作、文件更新、恢复与插件重新加载。

**Blocked by:** 01 — 当前段落查询；03 — 笔记更新与失败恢复（03 已由 02 阻塞）。

**Status:** resolved

## Context

依据 [Lite spec](../spec.md)。本票将前面路径整合为可安装、可复现、可验收的本机交付，独立安装检查属于实施验收，不是新增选型实验。

已有探针证明当前 Mac 上 Zvec、对应 binding 和 detect-libc 的独立运行组合约 30 MiB，可完成关键词操作。但尚未完成其在独立安装版 Obsidian 中的 E2E。

## Acceptance criteria

- [x] 提供可重复的当前 macOS ARM64构建/安装步骤，包含 Zvec公开库、对应native binding与Jieba资源；从插件安装位置解析，不硬编码或软链接到开发仓库。
- [x] 不为关键词检索打包整个 ZG、node-llama-cpp或新模型缓存，继续使用已有本地Ollama设置。
- [x] 部署保留目标插件设置，关键词数据与现有 IndexedDB不被运行文件覆盖；不把旧三文件复制流程误称为完整native部署。
- [x] 独立测试Vault可启动插件、加载native库、查询当前段落并在原侧边栏展示两路融合结果，选区与全选查询可用。
- [x] 光标换段、快速输入、换文件与面板隐藏/恢复后，旧响应不会更新当前结果，自动工作状态正常。
- [x] 点击来源打开正确文件和位置；展开、链接与引用操作继续可用；没有误标的余弦分数或旧展开阈值。
- [x] 在该安装中新增、编辑、移动与删除文件以及应用范围后，两路结果更新且不出现已删除或已排除片段。
- [x] 覆盖至少一个缓存同步/恢复失败路径、重建取消或失败保留旧索引路径，以及插件重新加载后恢复混合查询。
- [x] 插件关闭/重新加载正确释放native资源，没有锁残留导致后续查询或同步失败。
- [x] 真实Obsidian E2E可复现，保留精简摘要和可检查结果；使用确定的完整测试Vault路径，避免同名Vault误操作。
- [x] 运行完整 typecheck、测试、构建；修复本次改动导致的失败并重跑受影响检查。
- [x] 更新安装与运行说明，准确记录本机资源布局、已验证平台、仍未验证的平台及发布能力；不宣称Windows或BRAT已经支持。
- [x] 交付不操作正式Vault、不发布、不同步Windows目录；用户已有工作区修改与实验材料保持。用户最新 implement 指令明确要求提交，仅提交本次实现。

## Implementation constraints

只解决当前Mac可用的自包含运行目录。可以给出专门本机安装命令，不默认实现native自动下载器、跨平台升级框架或CI矩阵。

构建与同步变化不得静默部署到其他平台或覆盖现有配置/索引。若已有测试Vault布局会直连正式工作区，先明确目标和隔离方式。

E2E操作遵循真实Obsidian相关工具说明；清理测试文件使用trash。日志放在工作区外或被忽略调查目录，保留结果索引。
