# 03: 笔记更新与失败恢复

**What to build:** 用户新增、编辑、移动或删除笔记，以及应用范围、取消操作、重新启动后，两路检索始终基于同一份已提交内容。关键词缓存失效可以恢复，不需要删除或重建已有向量索引。

**Blocked by:** 02 — 原侧边栏接通混合检索。

**Status:** resolved

## Context

依据 [Lite spec](../spec.md)。02 已提供可查询的混合路径和快照失效保护；本票在该路径上完成高效增量同步、用户操作状态和恢复。

IndexedDB 仍是唯一 durable 真相源。关键词库只是派生缓存，不重新执行文件扫描、正文语义比较或 embedding，也不引入双库事务和新索引代管理。

## Acceptance criteria

- [x] 新增、正文修改、标题或文件名修改、文件/目录移动、删除后，成功提交的新快照反映到两路结果；旧正文、旧路径与已删除来源不会继续作为当前命中返回。
- [x] 正常小改动使用片段增删替换或最小差异同步，不每次重建整个关键词库；更新缓存不增加文档 embedding 调用。
- [x] 只有成功提交的片段进入关键词库；准备中、确认未通过、取消、计划过期或提交失败的候选内容不可被检索。
- [x] 同步中收到新提交或插件卸载时，旧同步不能标记新快照已完成，失效缓存不得冒充最新。
- [x] 设置保存仍只改变期望范围。范围成功应用后两路使用新的有效快照；取消/失败后 pending 和已有有效范围行为保持，普通大规模更新 deferred 不阻塞明确的手动范围应用。
- [x] 全量重建取消/失败继续使用旧索引；成功提交后才切换关键词快照；原有 durable commit 与 stale-plan 校验保持。
- [x] 清除本地索引后关键词缓存同步失效，不返回已清除内容，不删除笔记或设置。
- [x] 插件重启、缺少/损坏关键词缓存、同步失败后可以从当前已提交快照恢复；恢复不要求清除 IndexedDB 或重新 embedding。
- [x] 关键词同步失败时显示准确状态与重试入口；重试成功才恢复混合查询，不通过静默纯向量回退掩盖失败。
- [x] 面板隐藏时不新发起自动同步/查询；恢复可见时先对账与处理既有队列，再提供一致的混合结果。手动操作沿用既有授权与状态机制。
- [x] 大批片段同步分批处理，避免不必要的长时间主线程阻塞；检查卸载与快照变化，关闭 native 资源，不承诺 native 同步操作可即时中断。
- [x] 回归覆盖更新失败后恢复、删除残留、同步中快照变化、范围取消和重启恢复；通过公开 seam 测试，不依赖内部私有方法。
- [x] typecheck、相关测试和构建通过；现有语义复用、取消、范围、恢复与可见性测试不因接入词法库被删除或放宽。

## Implementation constraints

缓存对应记录、失效与重建使用最简单充分机制。不得让 Zvec 成为另一套独立文档真相源，不移植 ZG 的文件级更新或 daemon。不默认复制整库、维护镜像 Vault或将索引规则改成接受部分更新。

native底层增删替换已由调查探针验证，但缓存整体一致性没有实现；本票负责这一实际工程问题，不重复选型验证。

## Verification and handoff

在独立临时库保留可复现的故障注入结果。关键路径包括：提交成功但关键词同步失败，随后重试；同步期间到达更新提交；取消范围应用后恢复查询。验证的是查询内容和用户状态，而非仅更新函数调用次数。

说明缓存如何识别当前快照、如何恢复，以及 04 在真实 Obsidian 中需要重跑的操作。未经明确要求不提交、不发布、不操作正式 Vault，保留已有用户工作。
