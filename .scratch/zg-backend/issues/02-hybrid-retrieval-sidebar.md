# 02: 原侧边栏接通混合检索

**What to build:** 用户使用原 Palimpsest 发起查询时，系统在当前已提交的笔记片段上同时执行关键词与向量召回，通过 RRF 排名后在原侧边栏展示，保留正确来源与写作操作。

**Blocked by:** None (can start immediately).

**Status:** resolved

## Context

依据 [Lite spec](../spec.md) 和 [ZG 拼装清单](../zg-assembly-map.md)。可直接使用当前查询来源，不依赖 01 的当前段落变更。

已在 Node 探针中确认：Zvec 0.7.1 的独立 FTS collection 可以使用 Jieba/lowercase，接收现有分块，排除 YAML，支持替换、删除、过滤与重新打开。不必再以独立选型实验阻塞实施。

## Acceptance criteria

- [x] 直接使用锁定版本的 Zvec 公开接口，不加载完整 ZG；关键词 collection 使用其相同的 FTS、Jieba 和 lowercase 设置，不要求向量字段。
- [x] 关键词输入来自现有已提交片段的正文、文件名与标题上下文；合法 YAML 不因再次读取原文件而进入检索。
- [x] 保留 Ollama、原模型与向量输入、现有 IndexedDB 和分块，不迁移或清除用户索引，不因新增关键词库要求重新 embedding。
- [x] 派生关键词索引按 Vault 隔离并绑定片段快照；本票即保证快照变化后旧索引不能继续作为最新关键词结果返回。初期允许失效后重建，03 再完善增量同步与恢复，不把数据正确性延后。
- [x] 自动构建只接受当前已成功提交的片段，受现有可见性与卸载控制；失效构建结果不得发布。
- [x] 查询产生两路较宽且有限的候选排名，先融合再应用最终数量、每文件限额和去重；不把现有最终前五条当作全部向量候选。
- [x] 当前文件与有效范围过滤不会因先截断候选而错误耗尽结果；两路对应同一片段快照，查询期间快照改变则结果失效。
- [x] RRF 使用每路从 1 开始的排名、常数 60，缺席一路不贡献，同一路重复片段不重复贡献，并使用稳定的并列排序规则。
- [x] 受控输入验证关键词候选可以改变最终排名，向量独有候选仍然可进入结果；同时验证真实 Zvec 关键词查询，不以纯 mock 代替底层集成。
- [x] 结果展示不依赖携带向量，不把融合值冒充余弦相似度、准确率或相关概率。
- [x] 移除卡片余弦分数与相似度展开阈值，保留按前几条展开和手动展开；旧保存阈值字段不解释成新阈值，也不触发向量重建。
- [x] 原卡片原文、标题、文件与行号跳转、链接、引用和外观设置正常；不另建实验 UI。
- [x] 关键词库尚未就绪或 native 加载失败时明确显示状态和可继续操作入口，保留已有结果；不静默改用纯向量或旧关键词库。
- [x] typecheck、相关测试与构建通过。原生依赖声明与开发运行加载随本票接通；04 完成独立安装部署与真实 Obsidian 完整验收。

## Implementation constraints

优先提供一个紧凑的混合检索模块，以已提交片段快照与查询为公开测试面。候选打分与最终选择的必要调整随本路径完成，不另设通用后端框架或大范围水平重构。

不新增 CLI、MCP、daemon、ripgrep、node-llama-cpp、模型下载、用户词典、替代关键词后端切换或复杂调参。禁止把开发仓库绝对路径写入正式运行代码；可依赖工程内已安装的固定版本依赖，部署布局由 04 完成。

## Verification and handoff

沿用查询生命周期、结果展示和检索行为测试先例，回归覆盖候选截断顺序、两路重复贡献、当前文件排除与快照失效。记录候选预算及派生索引接口，交给 03 增量同步。

测试 native 失败与模型失败必须保护可见状态及恢复入口，而不只是断言抛错。不得报告等价于 ZG 或保留某个效果百分比。

未经明确要求不提交、不发布、不操作正式 Vault，保留用户已有修改。
